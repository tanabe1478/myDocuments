# 書き心地とレイアウトの方針（Run 5）

Run 11 でリストの継続、Run 12 で記号の表示とリンクを開く操作（ADR-004）を足した。

仕様の原則 1「書くことが主役」、UI-01、UI-02、UI-05、ED-02、ED-03、ED-07 に沿って決めた挙動をまとめる。実装は `src/editor/`、`src/features/`（同梱の部品。Markdown の見た目は `src/features/markdown/`）と `src/styles.css`。

## 視線の位置

カーソルが表示領域の下 3 割（上 3 割）に入ったら、カーソル行がその境目に来るまでスクロールする。文末で書き足しても、カーソルが画面の下端に張り付かない。CodeMirror の `scrollMargins` で与えるので、スクロールは 1 回の即時の移動で、Reduced Motion でも動きは付かない。タイプライターモードが ON のときは、中央に保つ既存の動作に任せ、この余白は足さない。

## 段落間隔

空行（空白だけの行を含む）の高さを `paragraphSpacing` で決める。単位は本文の行高に対する倍率で、既定は 0.6（保存済みの値がなければ）、範囲は 0〜3。空行の行高は `行高 × paragraphSpacing`。見出し前の余白も同じ値を基準にする（`行高 × 文字サイズ × paragraphSpacing × 0.8`）。

- 以前は em 単位で、見出し前の余白にだけ効いていた。範囲を変えていないので、旧い保存値は読み込める（保存値 1 は、空行が本文 1 行分、つまり変更前と同じ高さになる）。
- 余白は行の高さ（`line-height`）で作り、`margin` は使わない。CodeMirror は行の高さを margin を含めずに測るため、margin だと上下キーが行を飛ばす。
- 0 でも空行は 4px 残す。高さ 0 の行は、カーソルが見えず、クリックでも選べない。
- コードフェンスの中の空行は、書いたとおり本文 1 行の高さのまま。
- 上下キーの移動は、`src/editor/codemirror/verticalMotion.ts` で補正する。CodeMirror は、カーソルの下端（上端）から半行ぶん先の位置を探して移る。半行より低い空行（段落間隔を詰めたとき）は、探す位置を越えて飛ばされる。標準の移動が論理行を 2 行以上動かしたときだけ、隣の行に移し直す。

## ぶら下げインデント

リスト項目（`-`、`*`、`+`、`1.`、`1)`、タスク、入れ子）と引用（`>`、`> >`、引用の中のリスト）が折り返したとき、2 行目以降を行頭の記号の後ろに揃える。

- 行の `padding-left` と負の `text-indent` を、記号部分の幅（em）で付ける。幅は、記号の文字列を実際のフォントと字間で測って決める（フォント・字間が変わったら測り直す）。測れない環境（テストの jsdom など）では 1 文字 0.6em で概算する。
- 対象は、構文木でリスト項目または引用に入っている行だけ。コードフェンスの中、水平線（`- - -`）は対象外。
- IME の変換中も、変わるのは行の属性（class と style）だけで、変換中のテキストノードは作り直されない。記号を隠した行では、見える幅（隠した記号を除き、`•` とチェックボックスは固定の幅の箱）に揃える（ADR-004）。

## Tab / Shift+Tab

本文にタブ文字は入れない。

- リスト項目: Tab で字下げする。箇条書きは 2 スペース、番号付きは記号の幅（`1. ` なら 3、`10. ` なら 4）。Shift+Tab で戻す（行頭で止まる）。
- 引用: Tab で引用の段を 1 つ深くする（`> ` を足す）。Shift+Tab で 1 段戻す（1 段のときは何もしない）。
- 複数行の選択: 選んだ行すべてに適用する。リストと引用以外の行は、Tab で 2 スペース字下げする。空行は変えない。
- それ以外の行（選択が 1 行以内）: Tab は何もしない。タブ文字も入れず、フォーカスも動かさない。Shift+Tab は行頭の空白を 2 つまで消す。
- Esc を押した直後の Tab / Shift+Tab は、本文の外へフォーカスを移す（CodeMirror の `indentWithTab` の推奨作法）。Esc の後に別のキーを押すか、フォーカスが外れると解除する。検索パネルを閉じる Esc は数えない。F6 での移動も、今までどおり使える。

## Enter でのリストの継続

リスト項目（`-`、`*`、`+`、`1.`、タスク、入れ子、引用の中のリスト）で Enter を押すと、次の項目の記号を続ける。番号付きは次の番号（後ろの番号は付け直す）、タスクは `- [ ] `、入れ子はインデントを保つ。空の項目で Enter を押すとリストを終える（入れ子は 1 段戻す）。項目の途中で押すと、後半が次の項目になる。この基本の挙動は `@codemirror/lang-markdown` の `insertNewlineContinueMarkup` による。

項目の間に空行のあるリスト（loose list。`- a`、空行、`- b` のように、項目が段落として離れているリスト）では、lang-markdown は「リストの形を保つ」ために、次の項目の前にも空行を入れる。書き手には、Enter を押しただけで意図しない空行が挟まるように見える。そこで設定 `listContinuation` で選べるようにした。

- `tight`（既定、設定画面「編集」の「空行を入れない」）: loose list でも空行を入れず、改行と記号だけを入れる。tight list の空の 2 項目目でも、空行を入れない（下記）。
- `preserve`（「リストの形に合わせる」）: lang-markdown の既定のまま、loose list では次の項目の前にも空行を入れる。

- 実装は `src/features/list-continuation/listContinuation.ts`。`tight` のときだけ、lang-markdown のコマンドを実行して得た transaction から、継続のために足された空行だけを取り除く（「改行、空行、改行、記号」の 3 行の挿入だけが対象）。空の項目での終了、番号の付け直し、引用の継続、複数カーソルはそのまま通す。`preserve` は lang-markdown 自身の Enter に任せるので、挙動は変えない。
- tight list（空行のないリスト）の空の 2 項目目で Enter を押したとき、lang-markdown の既定は、空の項目の前に空行を入れて、リストを loose にする。`tight` では、これも止める（`insertNewlineContinueMarkupCommand({ nonTightLists: false })`）。止めたときは、空の項目の記号を取り除いて、リストを終える（1 項目目や 3 項目目以降の空の項目と同じ。入れ子は 1 段戻る）。例: `- a` の次の `- ` で Enter を押すと、`- a` と、記号のない空の行（カーソルがある）になる。`preserve` は、これまでどおり空行を入れる（Run 12、N4）。
- 変更はすぐ編集中の文書に効く。Compartment で切り替えるので、文書を開き直す必要はなく、`setText` で state を作り直しても今の値で始まる。
- IME の変換中の Enter は、今までどおり何もしない（`insertNewlineContinueMarkup` と同じキー割り当ての経路）。Undo は 1 回で Enter の前に戻る。
- .txt と .text は Markdown の言語を持たないので、もともとリストを続けない。設定にかかわらず今と同じ（通常の改行）。
- 設定画面の「編集」の節は「外観」の後。保存値が範囲外・不正なら `tight` に戻る。

## 本文面

- 紙の幅は設定の `surfaceWidth`。既定の `fill`（窓いっぱい）は本文の領域いっぱいで、影はない。`text`（本文に合わせる）は、以下の幅で、枠線はなく、淡い影（ライトとダークで別の値）で背景から浮かせる。どちらも、1 行の長さは `maxWidthPx` で決まり、本文の列は本文の領域（サイドバーを除いた領域）の中央。
- `maxWidthPx` は、左右の内側余白を除いた行の長さを表す。内側余白は行の外側に取る。余裕があるときは左右 56px、窓が狭いときは行長を保てる範囲で縮め、最小 20px。それでも足りなければ行長のほうが縮む。式は `src/editor/layout.ts`（CSS の `clamp` と同じ）。
- `text` のときの本文面の幅は、行長 + 左右の内側余白で、本文と同じ。
- 設定画面の「外観」に「1 行 約 N 字（全角）」を表示する。実際の行の幅を、文字サイズ × (1 + 字間) で割った値。禁則で、実際は 1 文字ほど前後する。

## 字間と折り返し

- `letterSpacing`（em、範囲 0〜0.15、既定 0.02）を設定画面の「外観」で調整できる。見出しでは、見出しの文字サイズに比例する。
- 長い URL や英単語は、本文の幅で折り返す（`overflow-wrap: anywhere`）。日本語の禁則は `line-break: strict`（小書きの仮名や長音を行頭に置かない）。

## Markdown の見た目

- コードフェンスの開始・終了行を含む行に、淡い背景帯。左右に少しはみ出し、文字を帯の端から離す。
- 引用の行の左（本文の余白の中）に細い縦線。続く行で 1 本につながる。
- 記号の表示（設定 `markupDisplay`、設定画面「外観」の「記号の表示」）。既定の `cursorLine`（カーソルのある行だけ）では、カーソルのある行と、選択にかかる行だけ記号を薄く表示し、ほかの行は記号を隠して整形して表示する（ADR-004）。`always`（常に表示）では、すべての行で記号を薄く表示する。保存されるテキストと、コピーした文字列は、どちらでも変わらない（隠すのは表示だけ）。
  - 隠す対象: 見出し（ATX）の `#`、箇条書きの記号（`•` に置き換え）、タスク（チェックボックスの形に置き換え。次の項目のとおり、クリックで切り替える）、インラインリンクの `[` と `](URL)`（自動リンクは `<` `>`）、強調と取り消し線の記号、インラインコードのバッククォート、引用の `>`。
  - 隠した行のチェックボックスは、修飾キーなしの左クリックで完了と未完了を切り替える（文書の `[ ]` と `[x]` の 1 文字だけを書き換える。カーソル・選択・スクロール位置は動かず（タイプライターモードでも中央合わせをしない）、Undo 1 回で戻る。入れ子、引用の中、`*` と `+` のタスクも同じ。ポインタは `pointer`、`role` は checkbox）。本文のクリック、カーソル行の `[ ]`、「常に表示」、修飾キー付きのクリック、右・中クリック、IME の変換中は切り替えない。キーボードでの切り替えはない（ADR-004）。
  - 対象外（今のまま）: コードフェンス、インデントコード、HTML ブロック、frontmatter、エスケープ、参照リンク、画像、番号付きリストの番号、Setext 見出しの下線。`.txt` と `.text`。
  - 行の表示を切り替えるのは、選択のかかる行が変わったときだけ。入力中の行は常に記号を見せているので、入力の途中で見た目が変わらない。IME の変換中は、他の行も含めて切り替えを保留し、変換が終わってから反映する。
  - ぶら下げインデントは、隠した行では見える幅に揃える（`•` とチェックボックスは固定の幅の箱。引用だけの行は字下げしない）。
  - 記号を隠しても、見出しの文字サイズ・行の高さ・引用の縦線は変わらない。
- リンクは、⌘+クリック（macOS）、Ctrl+クリック（Windows と Linux）で、既定のブラウザで開く。http と https だけで、それ以外はトースト「このリンクは開けません」。修飾キーを押している間、リンクの上でポインタが変わる。普通のクリックはカーソルを置くだけ。
- 配色はライト・ダークの両方で、コードの文字が背景帯の上で AA（4.5）を満たし、縦線が本文面に対して 3 以上になるよう、`src/canvas/markdownColors.test.ts` で確かめている。

## 執筆中の UI

`autoHideChrome` の既定は ON。保存済みの値があれば、それを尊重する（false が保存されていれば隠れない）。初回起動で入力を始めるとバーが隠れる。ポインタの移動、フォーカス、F6 で戻る。

## 未検証

- 実機の IME（Microsoft IME、macOS の日本語入力、Mozc）での変換中の挙動。e2e は Chromium の CDP による模擬。記号を隠した行の前後や、見出し・リストの行での変換も、模擬だけ（ADR-004）。
- リンクを実際に既定のブラウザで開く操作。e2e はメモリ bridge が渡された URL を記録するだけで、ブラウザは開かない。ネイティブ側の検査は cargo test。
- Windows 11 と Ubuntu 24.04 の実機のフォントでの、折り返し位置とぶら下げの幅。測定は Chromium（macOS）のみ。
- WebKit（macOS の WKWebView）での `line-break: strict` と `overflow-wrap: anywhere` の折り返し位置。
