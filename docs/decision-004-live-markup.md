# ADR-004: カーソルのない行で Markdown の記法を隠す（記号の表示）と、⌘/Ctrl+クリックでリンクを開く

## Status

Accepted（2026-11-02、承認者: プロジェクトオーナー）。仕様 §5.2 の「記号の自動非表示は IME と範囲選択への影響を検証してから有効化する」を、Run 12 で検証して有効化する。`docs/writing-feel.md` の「記号は表示したまま（自動非表示はしない）」と、`markdownDecorations.ts` の冒頭の「非表示にはしない」を、この ADR で改める。仕様の文書そのもの（`docs/spec/`）は書き換えない。この ADR が、仕様に対する変更として優先する。

## Context

利用者がドッグフーディング（自分で使いながらの検証）で、次を求めた。

> リンクはカーソルがその行にいる時だけ markdown 表記で、カーソルが他の行に行ったら通常のリンクとしてレンダリングされてほしい。これは見出しや箇条書きにも言える。

これまでは、記号（`#`、`*`、`[]()`、`>` など）を薄く表示するだけで、隠さなかった。仕様 §5.2 は、自動非表示を、IME と範囲選択への影響を確かめてからにする、としていた。

## Decision

利用者の判断:

- 隠す記法は、見出し・リスト・リンク・強調・取り消し線・インラインコード・引用・タスクのすべて。
- 既定で有効。設定画面の「外観」の「記号の表示」で、「常に表示」に戻せる。
- ⌘+クリック（Windows と Linux は Ctrl+クリック）で、リンクを既定のブラウザで開く。

### 設定

`Preferences.markupDisplay`（`'cursorLine'` | `'always'`、既定 `'cursorLine'`）。範囲外・不正な保存値は既定に戻る。変更はすぐ効く（Compartment で切り替え、`setText` で state を作り直しても今の値で始まる）。`.txt` と `.text` には効かない（もともと装飾がない）。`always` は、これまでと全く同じ見た目。

### 表示の規則

`cursorLine` のとき、カーソルのある行と、選択範囲にかかるすべての行（複数カーソルならそれぞれの行）では、これまでどおり記号を薄く表示する。それ以外の行では、次のように表示する。

| 対象 | 表示 |
|---|---|
| 見出し（ATX） | 行頭の `#` と直後の空白を隠す。文字サイズと太さは変えない。閉じる `#` と、Setext 見出しの下線（`===`、`---`）は、薄く表示したまま |
| 箇条書き（`-` `*` `+`） | 記号を `•` に置き換える（入れ子も `•`）。番号付き（`1.` `1)`）はそのまま |
| タスク（`- [ ]`、`- [x]`） | 記号とチェックボックスを、チェックボックスの形（未完了・完了）に置き換える。チェックボックスの上の、修飾キーなしの左クリックで完了と未完了を切り替える（Run 13。下の「タスクの切り替え」）。番号付きのタスクは対象外 |
| リンク | インラインリンク `[文字](URL "題")` の `[` と `](URL "題")` を隠し、文字をリンクの色と下線で表示する。自動リンク `<https://...>` は `<` `>` を隠す |
| 強調・取り消し線 | `**` `__` `*` `_` `~~` を隠し、装飾だけを残す |
| インラインコード | バッククォートを隠し、等幅と色を残す |
| 引用 | 行頭の `>` と、直後の空白 1 つを隠す（入れ子の `> >` も）。左の縦線と色は残す |

対象外（今のまま）: コードフェンスの中（フェンス行を含む）、インデントコード、HTML ブロック、frontmatter（`focusRange.ts` と同じ判定: 1 行目の `---` から、次の `---` まで）、エスケープ `\*`、参照リンク `[文字][ref]` と参照の定義行、画像 `![alt](src)`、GFM の裸の URL（もともと記号がない）。

- 隠す範囲を決めるのは、純関数 `src/editor/liveMarkup.ts`（構文木と文書だけを読む。表示は関与しない）。範囲は 1 行の中に収める（行をまたぐ記号は、行ごとに分ける）。CodeMirror の `Decoration.replace` と、固定の幅の箱（ウィジェット）で表示するだけで、文書は書き換えない。保存されるテキストにも、コピーした文字列にも、記号がそのまま入る。
- ぶら下げインデント（リストと引用の折り返し）は、隠した行では、実際に見える幅に揃える。`•` とチェックボックスは固定の幅の箱（1em）で、残りの文字（字下げ、空白、番号）は実際のフォントで測る。引用だけの行は、記号を隠すので字下げしない（縦線は、これまでどおり左の余白に出る）。
- 引用の縦線、見出しの文字サイズ、行の高さは、隠しても変わらない（Playwright で、隠す・見せるの前後で行の位置が同じことを確かめた）。

### 選択の行の扱い

行の表示を切り替えるのは、選択のかかる行が変わったときだけ。入力中の行は、いつも「カーソルのある行」なので、入力の途中で同じ行の見た目が変わらない。選択が行の頭で終わるときも、その行を含める（カーソルがその行にあるので）。カーソルや選択が、隠した記号の位置に入るときは、その行が表示側に切り替わるので、記号が見える。

### IME の変換中の保留

IME の変換中（`view.compositionStarted`）は、隠す・見せるの切り替えを、他の行も含めて保留する。隠している範囲は、本文の変化に位置だけ追従させる。変換が終わってから（`compositionend` の 60ms 後。フォーカスモードと同じ待ち）、現在の選択に合わせて反映する。変換中は、ほかの行の DOM 要素を作り直さない（e2e で、行の要素が同一のままであることを確かめた）。

### 仕様 §5.2 の条件をどう確かめたか

| 条件 | 確かめ方 |
|---|---|
| IME | `tests/e2e/live-markup.spec.ts` (d)。Chromium の CDP（`Input.imeSetComposition` / `insertText`）で変換を模擬し、記法を隠した行の前の行、見出しの行（記号の直後）、リストの行（記号の直後）、引用の行の末尾で、変換中の表示が壊れず、ほかの行の DOM 要素が変わらず、確定した文字列が正しい位置に入ることを確かめた。変換の取り消し、変換中の外部 `setText` の保留も確かめた。単体テスト（jsdom）で、変換中の選択の移動が保留され、変換後に反映されることを確かめた。既存の `ime.spec.ts` と `writing-feel.spec.ts` の IME の検査（記号を見せる設定 `always` で今までどおり通る） |
| 範囲選択 | 同 (b)(e)。Shift+矢印、mac の Shift+Ctrl-n/p、マウスのドラッグ、ダブルクリックで、隠した記号をまたいで選択でき、選択した文字列が記号を含めて正しいこと。選択にかかる全行で記号が見えること。コピーした文字列に記号が入ること。既存の `cursor-motion.spec.ts` と `vertical-selection.spec.ts` を、`always` と `cursorLine` の両方で通した |
| 本文を変えない | 同 (c)。隠した状態で編集して保存したバイト列が、記法を含めて 1 バイトも変わらないこと。Undo / Redo |
| ぶら下げインデント | 同 (f)。隠した行の折り返しの 2 行目以降が、`•`・チェックボックス・番号の後ろに揃う（許容 ±2px）。`always` の既存の検査は残した |
| タイプライター・フォーカス・読む位置 | 同 (j)。行の表示の切り替えで、本文の位置が飛ばない |

実 IME（Microsoft IME、macOS の日本語入力、Mozc）での確認は、未実施。Chromium の模擬だけで、実機の IME は、変換中の DOM の扱いが異なることがある。有効化の前提としては、模擬での確認と、変換中は DOM に触れない作りで足りると判断した。実機で問題が出たら、設定で `always` に戻せる。

### リンクを開く

- ⌘+クリック（macOS）、Ctrl+クリック（Windows と Linux）で、リンク（インラインリンクの文字と URL の部分、自動リンク、裸の URL）を既定のブラウザで開く。記号を見せている行でも隠している行でも同じ。カーソルと選択は動かさない。普通のクリックは、これまでどおりカーソルを置くだけ。macOS の Ctrl+クリックは右クリックの扱いなので、使わない。
- 開けるのは http と https だけ（ホストのあるもの）。それ以外（相対パス、`#`、`mailto:`、`file:`、`javascript:` など）は開かず、「このリンクは開けません」とトーストで知らせる。参照リンクは、リンク先を持たないので対象外。
- 修飾キーを押している間、リンクの上でポインタの形を変える（`cursor: pointer`）。
- 検査は、フロントエンド（`src/platform/externalUrl.ts`）とネイティブ側（`src-tauri/src/external.rs`）の両方で行う。ネイティブ側が正本で、`tauri::Url` で解析し、スキームが http / https で、ホストがあり、`scheme://host` の形で書かれたものだけを通す（解析器が補う `https:example.com` のような崩れた書き方、前後の空白、8192 バイトを超えるものは、InvalidInput）。
- ネイティブ側は新しいコマンド `open_external_url(url)`。検査を通ったものを、`tauri-plugin-opener` 2.7.2 の Rust の API（`OpenerExt::open_url`）で開く。プラグインは Rust 側で `init` するが、プラグインの JavaScript 向けのコマンド（`opener:default` など）は capabilities に足さない。Web UI から任意の URL やパスを開けないようにするため。プラグインが `<a>` のクリックを横取りする注入スクリプトも、無効にした（`open_js_links_on_click(false)`）。Web UI がネイティブに頼める入口は、`open_external_url` だけ。JavaScript のパッケージ（`@tauri-apps/plugin-opener`）は足さず、`package.json` と `package-lock.json` は変えない。
- `DocumentBridge.openExternalUrl(url)` を足した。メモリ bridge（e2e）は、渡された URL を `openedUrls` に記録するだけで、ブラウザを開かない。

### タスクの切り替え（Run 13）

利用者がドッグフーディングで「todo はクリックでチェックボックスを外せて良いのでは」と求め、次の仕様に合意した。

- 記号を隠した行のチェックボックス（`.cm-md-task`）を、修飾キーなしの左クリック（mousedown、button 0）すると、文書の `[ ]` と `[x]` の中の 1 文字だけを書き換える（`[ ]` → `[x]`、`[x]` と `[X]` → `[ ]`）。ほかの文字は変えない。入れ子、引用の中（`> - [ ] a`）、記号が `*` と `+` のタスクも同じ。番号付きのタスクは、もともとチェックボックスを出さないので対象外。
- クリックでカーソル・選択・スクロール位置は動かない（CodeMirror に mousedown を渡さず、`preventDefault` する）。タイプライターモードは、文書が変わるとカーソル行を中央へ合わせ直すので、切り替えの transaction（`userEvent` は `input.toggle-task`）では合わせ直さない（ポインタでの選択、`select.pointer`、と同じ扱い）。フォーカスモードは行の表示だけを変えるので、スクロールに影響しない。その行は隠したまま、形だけが変わる。エディタのフォーカスが外れているときは、Undo のキーが効くようにフォーカスだけ戻す（選択は state のまま）。
- 1 回の切り替えは Undo 1 回で戻り、Redo でやり直せる。`userEvent: 'input.toggle-task'` を付けた通常の transaction で、`isolateHistory`（`full`）により、前後の入力と 1 つの Undo にまとめない。編集済みの表示と自動保存は、通常の入力と同じ経路（`changeListeners`）を通る。
- 書き換える位置は、チェックボックスのウィジェットの今の位置（`view.posAtDOM`）から、`liveMarkup.ts` の task の範囲（Run 12 で隠す範囲を作るものと同じ）で決める（`src/editor/codemirror/taskToggle.ts` の純関数 `taskToggleAt`）。ウィジェットの DOM が再利用されても、古い位置は使わない。
- すばやく 2 回クリックすると 2 回切り替わる（元に戻る）。語の選択は起きない。
- ウィジェットは `role="checkbox"`、`aria-checked` が状態に合う（Run 12 までは `role="img"`）。`aria-label` は、状態を `aria-checked` が表すので、固定の「タスクの完了」にした（Run 12 までの「完了」「未完了」は、`aria-checked` と二重になるため）。チェックボックスの上のポインタは `pointer`。
- 切り替えず、今までどおり（カーソルを置く・選択を伸ばす）にするもの: チェックボックスの右の本文のクリック、カーソル行（記号が文字で見えている行）の `[ ]` のクリック、設定が「常に表示」のとき、修飾キー付きのクリック（Shift は選択の拡張、⌘/Ctrl はリンクを開く操作と同じ扱い。Alt も）、右クリックと中クリック、IME の変換中（`view.composing`。変換中は何もしない）。
- 検査: `src/editor/codemirror/taskToggle.test.ts`（書き換える位置と文字）、`CodeMirrorAdapter.test.ts`（jsdom で、transaction・選択・Undo/Redo・変更通知・切り替えない操作）、`tests/e2e/live-markup.spec.ts` (k)（保存したバイト列の差が 1 文字だけ、選択とスクロール位置と行の表示、Undo/Redo、入れ子・引用・`*`・`+`、切り替えない操作、2 回クリック、ポインタと role、IME の変換中。スクロール位置は、通常・タイプライターモード・フォーカスモード・両方の 4 通りで確かめた）。mac・windows・linux の偽装で通す。

### N4（Run 11 の Reviewer 注記）

設定「リストの継続」が「空行を入れない」（`tight`）のとき、空行のないリスト（tight list）の空の 2 項目目で Enter を押しても、空行を入れてリストを loose にしない。lang-markdown の `insertNewlineContinueMarkupCommand({ nonTightLists: false })` が止める動作で、止めたときは、空の項目の記号を取り除いてリストを終える（1 項目目、3 項目目以降の空の項目と同じ扱い。入れ子は 1 段戻る）。例: `- a` の次の `- ` で Enter → `- a` と、記号のない空の行（カーソルがある）。「リストの形に合わせる」（`preserve`）は、これまでどおり空行を入れる。

## Consequences

- 既定の見た目が変わる。記号を見たい利用者は、設定で「常に表示」にする。
- ぶら下げインデントの測り方、表示の切り替えの判断（選択の行）、IME の保留が、記法の表示に依存するようになった。`markupDisplay: 'always'` では、隠す範囲を一切作らないので、これらは従来と同じ経路になる。
- 記法の表示のために、行の装飾の再計算が増える（構文木をもう 1 回なぞる）。`npm run perf -- --quick --web-only` は完走した（78 項目を計測）が、基準値との比較（`perf:compare`）は行っていない。quick は標本が少なく、入力の遅延への影響は未確認。
- 既存の e2e のうち、記号が見えていることが主題だったもの（記号の色、ぶら下げインデントの位置、リストの行の IME）は、`markupDisplay: 'always'` を明示して今と同じ条件で確かめる。配置が主題のもの（上下の移動、ぶら下げインデント）は、`always` を残したうえで、`cursorLine` でも通ることを足した。

## 限界

- 実 IME は未検証（上記）。Windows と Ubuntu の実機も未確認（Playwright は navigator の偽装）。
- 隠した行をダブルクリックすると、1 回目のクリックでその行が表示側に切り替わり、記号の幅だけ文字が右へずれるので、2 回目のクリックが、ずれた後の文字に当たる。選ばれる語が、ポインタの下にあった語と違うことがある（選択そのものは、行の中の正しい範囲）。ドラッグでも、通る行が順に切り替わる。
- 上下キーで隠した行へ入ると、列は隠した記号の分だけ（記号の長さ程度）ずれる。行が飛ぶことはない。
- 構文木は、CodeMirror が解析を終えた範囲まで。長い文書で、解析が追いついていない範囲は、記号が見えたままになることがある（表示の範囲だけを対象にしている）。
- 複数行にまたがる記法（行をまたぐリンクや強調）は、記号のある行ごとに、その行にカーソルがあるかで決める。
- 表のセルの中の強調やリンクの記号は、隠す（表の区切り `|` と下線は、そのまま）。HTML ブロックの中は隠さない。表そのものを表の形で表示することは、ADR-006 で決めた（原文の表の中では、この規則が今のまま働く）。
- 記号を隠した行のコピーは、文書のテキストそのもの（記号を含む）。見えている文字列だけをコピーする機能は作っていない。
- チェックボックスの切り替えは、クリックだけ。キーボードでの切り替えは作っていない。アプリは複数カーソルを有効にしていないので、複数カーソルでの動作は、有効にした素の EditorView の単体テストだけで確かめた（UI からは作れない）。

## 判断を見直す条件

- チェックボックスの切り替えを、キーボードでもしたい要望が出たとき（Run 13 では作らなかった）。
- 実 IME で、変換中の表示や確定の位置に問題が出たとき。
- ダブルクリックやドラッグのずれが、日常の使い方で気になるとき（例: 切り替えを、ポインタが動いた後まで遅らせる）。
- 参照リンクと画像も隠したい要望が出たとき。
