# 没入型Markdownエディタ 仕様書（Draft v0.1）

- **文書種別**：製品仕様書 / 初期実装仕様
- **作成日**：2026-10-31
- **ステータス**：実装着手用ドラフト（未検証項目あり）
- **仮称**：Immersive Markdown Editor（製品名未定）
- **想定読者**：開発者、コーディングエージェント、レビュアー

## 1. プロダクトの目的

Windows・macOS・Ubuntuで動作する、軽量で没入感の高いローカルファーストMarkdownエディタを作る。

- **CotEditorから学ぶ**：起動・入力の軽快さ、堅牢なファイル編集、少ない機能、OS標準の操作を尊重する設計。
- **OmmWriterから学ぶ**：背景、環境音、余白、タイポグラフィによる集中できる執筆空間。
- **既存Markdownエディタから学ぶ**：標準Markdownとの互換性、成熟した編集エンジンの活用。

他製品の画面・商標・素材を模倣せず、独自の視覚言語を構築する。

### 1.1 プロダクト原則

1. **書くことが主役**：通常の執筆時に設定・AI・ナビゲーションUIが視界を占有しない。
2. **データの所有権**：ユーザーの文書はローカルの `.md` ファイル。独自形式へのロックインを作らない。
3. **軽さは実測する**：起動時間、入力応答、メモリ、スクロールを測定して改善する。
4. **3 OSで一貫した体験**：見た目、ショートカット、編集の意味を可能な限り統一し、OS固有の慣習は尊重する。
5. **保存で壊さない**：変更していない文書を書き換えず、外部変更と競合した際も無言で上書きしない。
6. **小さく作り、段階的に拡張**：AI機能やワークスペース管理は初期版の必須要件にしない。

## 2. 対象ユーザーとユースケース

### 2.1 想定ユーザー

- 技術記事、随筆、メモ、仕様書などをMarkdownで執筆する人。
- 装飾の多い統合開発環境より、静かな執筆環境を好む人。
- Windows・macOS・Ubuntu間で同じ執筆環境を利用したい人。

### 2.2 中核ユースケース

1. アプリを開くと、前回の執筆環境と未保存の草稿を復元できる。
2. 既存のMarkdownを開き、見やすい幅・行間・フォントで編集する。
3. 背景を変更し、雨・焚き火などの音を流して集中する。
4. 集中モードでは本文以外のUIを自動的に控えめにする。
5. 保存した `.md` をGit、別のエディタ、コーディングエージェントで引き続き利用する。
6. 別プロセスがファイルを書き換えた場合は、競合を認識して選択できる。

## 3. スコープ

### 3.1 MVP（P0）

- Windows・macOS・Ubuntu向けデスクトップアプリ。
- Markdownファイルの新規作成、開く、編集、保存、別名保存。
- CodeMirror 6を利用したMarkdownソース編集。見出し・強調・リンク等の読みやすい表示。
- 既存のMDEのMilkdownビジュアル編集を評価し、条件を満たす場合のみ切替モードとして採用（5.3参照）。
- 集中モード、フォーカスモード、タイプライターモード。
- フォント、文字サイズ、行高、本文最大幅、背景色・背景画像、背景オーバーレイ濃度の調整。
- アプリ内の環境音（雨／焚き火／カフェの3系統以上）と個別音量・ミュート。音はデフォルトOFF。
- ドキュメントの自動復旧、未保存変更表示、保存時の競合防止。
- 基本的なキーボード操作、スクリーンリーダー対応、Reduced Motion対応。
- 3 OSでのIME・描画・ファイル操作の自動/手動テスト。

### 3.2 次期版（P1）

- 背景動画、カスタム環境音ファイル、音のプリセット。
- 複数タブ、フォルダ/ワークスペース、アウトライン、検索と置換。
- テーマのエクスポート・インポート、アプリ内でのテーマ管理。
- Markdownライブプレビュー、PDF/HTML出力、画像のドラッグ&ドロップ。
- ビジュアル編集のMarkdown互換性改善と本格サポート。

### 3.3 将来検討（P2）

- AIエージェントによるレビュー、コメント、文章改善提案。
- 差分の提示と部分承認、作業履歴、Git連携。
- プラグイン／外部CLIの拡張ポイント。

### 3.4 非目標（MVP）

- アカウント、クラウド同期、共同リアルタイム編集。
- AIチャットや内蔵LLMを主画面に配置すること。
- Notionのようなデータベース・ブロック管理。
- 複雑なMarkdown拡張記法をすべて再現すること。
- 既存製品のUI・音声・画像素材をそのまま再現すること。

| UI-02 | 行高・段落間隔・フォント・文字サイズを変更可能にする | P0 |
| UI-03 | 背景色・グラデーション・ローカル背景画像を選択できる | P0 |
| UI-04 | 背景画像の明度やテキスト面のオーバーレイ濃度を調整できる | P0 |
| UI-05 | 執筆中は上部・下部ツールを自動非表示にでき、ポインタ移動やショートカットで再表示する | P0 |
| UI-06 | フォーカスモードで現在段落以外を弱く表示できる | P0 |
| UI-07 | タイプライターモードで現在行を縦方向中央付近に保持できる | P0 |
| UI-08 | 明・暗テーマと低コントラストでも読みやすい既定配色を備える | P0 |
| UI-09 | 背景動画を設定できる | P1 |
| UI-10 | 独自の見た目を保ちつつ、各OSの標準ショートカット・ウィンドウ操作に従う | P0 |

背景と装飾は読みやすさを損なわない。文字と背景のコントラストを常に確認できるようにし、背景を非表示にするアクセシビリティ設定を設ける。

### 4.3 サウンド要件

- 環境音はユーザー操作によって再生開始する（自動再生OFF）。
- 最低3種類のループ素材（雨、焚き火、カフェ）。各音の音量を0〜100%で調整できる。
- 複数音のミックス、フェードイン・フェードアウト、ミュートを提供する。
- 音声ファイルは配布・再利用可能なライセンスを確認し、帰属を記録する。
- 音量や再生状態は前回設定を記憶するが、次回起動時に無断で再生しない。
- OSの出力先変更、アプリの非アクティブ化、サスペンド復帰で破綻しないこと。

## 5. Markdown編集要件

### 5.1 主要機能

| ID | 要件 | 優先度 |
|---|---|---|
| ED-01 | UTF-8 Markdownファイルを開き、編集・保存できる | P0 |
| ED-02 | 見出し、強調、箇条書き、引用、コードブロック、リンクを入力・編集できる | P0 |
| ED-03 | Undo/Redo、選択、検索、コピー・ペースト、ドラッグ選択が正常動作する | P0 |
| ED-04 | Markdownソースモードでキャレット・IMEが安定動作する | P0 |
| ED-05 | 変更のないファイルを保存しても本文バイト列を変更しない | P0 |
| ED-06 | LF/CRLF、UTF-8 BOMの有無を可能な限り維持する | P0 |
| ED-07 | Markdownの見た目を執筆中に整える（ソース装飾・テーマ） | P0 |
| ED-08 | Markdownのビジュアル編集とソース編集を切り替えられる | 条件付きP0 |
| ED-09 | YAML frontmatter、表、数式、Mermaid、HTMLブロックを損なわない | P1 |

### 5.2 ソース編集の扱い

- **正本はファイルのMarkdownテキスト**。DOMやProseMirrorの内部モデルを唯一の正本にしない。
- MVPの標準モードはCodeMirror 6のソース編集。Syntax Highlightや装飾は表示上のものとし、文書内容に不要な自動変更を加えない。
- 入力中のcomposition eventsを尊重し、IME変換中に内容・DOM・キャレット位置を破壊しない。
- 見出しや強調の記号を薄く表示するなどの装飾は可能だが、記号の自動非表示はIMEと範囲選択への影響を検証してから有効化する。

### 5.3 ビジュアル編集モードの採用条件

MDEのMilkdownを再利用候補とするが、無条件にMVPの既定編集モードにはしない。

採用条件：

1. モード切替だけでは、ソースのMarkdownのバイト列が変化しない。
2. ビジュアル編集で意味的な内容が壊れない。記法の正規化が生じる場合は明示し、元ソースへ戻せる。
3. 日本語IMEの確定・再変換・取り消しがWindows/macOS/Ubuntuで安定する。
4. 表やフロントマターなど非対応ブロックを破壊せず、必要ならソースモードで扱う。
5. 大規模文書の入力遅延・スクロールの計測が許容範囲に収まる。

上記のいずれかを満たさなければ、ビジュアル編集はP1へ延期する。**ソースモードの安定性を犠牲にしてまでWYSIWYGを入れない**。

## 6. ファイル保存・復旧要件

| ID | 要件 | 優先度 |
|---|---|---|
| FS-01 | 新規、開く、保存、別名保存をOS標準ダイアログから行える | P0 |
| FS-02 | 未保存変更をUIに表示し、終了時には復旧可能な草稿を保持する | P0 |
| FS-03 | 保存時は一時ファイルへの書込・flush・置換を基本とし、失敗時に元ファイルを残す | P0 |
| FS-04 | 保存直前にmtime/サイズだけでなく内容ハッシュ等を使って外部変更を検出する | P0 |
| FS-05 | 編集中に外部変更を検知した場合、未変更なら再読込、未保存変更ありなら差分・再読込・保持を選択できる | P0 |
| FS-06 | 自動保存はクラッシュ復旧用のアプリデータを更新し、元の文書へ無断上書きしない | P0 |
| FS-07 | 外部編集や競合解決を行う場合も、バックアップまたは復元可能な内容を保持する | P0 |

保存処理の詳細はOSごとのファイル置換・アクセス権・ファイルウォッチャー挙動を考慮する。シンボリックリンクやネットワークドライブの扱いはPhase 0で方針を決める。

## 7. 技術アーキテクチャ（暫定）

### 7.1 推奨技術

- デスクトップシェル：**Tauri 2**。
- UI：**React + TypeScript**（MDEを再利用する場合）。
- ソースエディタ：**CodeMirror 6**。
- ビジュアルエディタ：**Milkdown / ProseMirror**（条件付き）。
- ネイティブ機能：**Rust + Tauri plugins**（ファイル、ダイアログ、通知、設定）。
- 背景・タイポグラフィ：CSS（レイアウトをOS固有のガラス効果に依存させない）。
- 環境音：Web Audio API（実機WebViewで検証）。
- テスト：Vitest等の単体テスト、Playwright等のWeb UIテスト、Tauri実機スモークテスト。

### 7.2 論理構成

```text
Desktop Shell (Tauri 2)
├─ Rust: File I/O / Watcher / Recovery / Permissions
├─ Web UI
│  ├─ Writing Canvas (layout / backgrounds / focus mode)
│  ├─ Markdown Engine Adapter
│  │  ├─ CodeMirror 6 (primary)
│  │  └─ Milkdown (conditional)
│  ├─ Ambient Audio Manager
│  └─ Preferences / Themes
└─ Local Markdown files (.md)
```

UIからRustへのアクセスは限定したコマンド境界にまとめ、編集エンジンは`EditorAdapter`等で包む。将来デスクトップシェルや編集エンジンを変更できる構造にする。

### 7.3 MDEを採用するかの判断

**MDE（https://github.com/sevenevesai/MDE、2026-10-31時点MIT）を第一候補として技術検証する。** フォークは確定事項ではない。

- 採用したい部品：Tauriブートストラップ、CodeMirror設定、Milkdown統合（条件付き）、ファイル監視、外部変更との競合表示、保存・復旧処理。
- 置き換える予定の部品：アプリシェル、ナビゲーション、テーマ、執筆キャンバス、環境音UI。
- 継承しないもの：今回の目的に直接関係しない複雑な機能。
- ライセンス確認：MDE本体のMIT表記だけでなく、依存ライブラリ、同梱フォント・音声・画像のライセンスと再配布条件を監査する。

Phase 0で品質や改造コストが不適合なら、**新規Tauriシェル + CodeMirror 6** へ切り替え、既存OSSは参考実装として利用する。

## 8. クロスプラットフォーム対応

### 8.1 初期サポート対象

- Windows 11（x64）
- macOS（Apple Siliconを必須、Intelは可能なら対応。サポートするmacOSバージョンはCIと実機検証で確定）
- Ubuntu 24.04 LTS（x64、GNOMEを初期検証対象。新しいLTSは追加検証）

Windows 10や他のLinuxディストリビューションはMVPの保証対象外とする。これは実装不能という意味ではなく、検証対象を絞るための初期方針。

### 8.2 WebView差異の注意

TauriはOSごとにWebViewの実装が異なる。見た目が似ていても、IME、フォント、選択範囲、`contenteditable`、音声コーデック、GPU合成などの実装差はあり得る。

- 日本語IMEは **Windows：Microsoft IME、macOS：日本語入力、Ubuntu：Mozc（IBusまたはFcitxの検証環境を記録）** で実施。
- 全画面切替、DPI/拡大率、異なるモニターへの移動、サスペンド復帰を確認する。
- WebViewやOSごとの差異はUIアダプターやCSSの範囲で吸収する。入力データの整合性に影響する差はリリースブロッカーとする。

## 9. 非機能要件と計測

### 9.1 計測項目

- プロセス開始→編集可能状態までの時間（cold/warmを分離）。
- 全プロセス合計の常駐メモリ（起動直後・空文書・100KB・1MB）。
- キー入力から描画反映までの遅延、IME確定後の反映遅延。
- 長文スクロール中のフレーム時間と引っ掛かり。
- 文書読み込み時間、保存時間、モード切替時間。
- パッケージサイズと依存コンポーネント。

### 9.2 テストデータ

- A：10KB、日本語の通常文章。
- B：100KB、見出し・箇条書き・リンク・コードブロック混在。
- C：1MB、長文と数百〜数千段落。
- D：複雑な表、コード、リンク定義、frontmatter、巨大な単一ブロックを含むストレス文書。

数値目標はPhase 0で同一条件の計測をして確定する。仮目標：通常文章の入力→描画遅延p95が50ms未満、100KB文書の開く操作がおおむね1秒以内。これらは**製品の現状実測値ではなく、計測によって調整する開発目標**である。CPU/GPU、WebViewバージョン、バックグラウンド負荷を記録し、比較は同条件で行う。

## 10. セキュリティとプライバシー

- デフォルトではネットワーク通信・テレメトリーを実施しない。
- ファイルシステム権限を選択されたファイル／ディレクトリに限定する。Tauriのcapabilitiesと各プラグインの権限設定を監査する。
- Markdown内のHTML、リンク、画像、埋め込みコンテンツは信頼できない入力として扱う。
- プレビューやビジュアル編集でHTMLを利用する場合はサニタイズし、スクリプトや危険なURLスキームを実行しない。
- リモート画像の自動読み込みはデフォルトOFFとし、プライバシー上の注意を表示する。
- バンドルした音声・画像・フォントの権利を確認し、第三者コンテンツを無断同梱しない。
- アップデート機構・署名・配布経路はP1までに整備し、未署名ビルドの制約を明示する。

## 11. 受入基準（Definition of Done）

**MVPは次のすべてを満たした場合に完了とする。**

1. Windows 11、macOS Apple Silicon、Ubuntu 24.04で起動・新規・開く・編集・保存・別名保存ができる。
2. 3 OSの日本語IMEで連続入力、変換、確定、キャンセル、改行、Undo/Redoに文字消失やカーソル飛びがない。
3. Markdownファイルの無編集の開閉、モード切替、明示保存で不要な本文変更がない。
4. 外部編集と未保存変更の衝突を検出し、無言の上書きが起きない。
5. 強制終了を模擬した後に未保存の草稿を復旧できる。
6. 背景画像、文字組み、集中モード、タイプライターモードが3 OSで動く。
7. 環境音を再生・停止・ミックス・ミュートでき、初回起動時に勝手に再生しない。
8. 10KB、100KB、1MBのサンプル文書で性能測定結果を記録し、重大な停止や入力不能がない。
9. ネットワーク通信、Markdownプレビュー、ファイルアクセスのセキュリティテストに合格する。
10. 依存ライセンス、画像・音声・フォントの権利表示、README、ビルド手順、既知の制約が整理されている。
