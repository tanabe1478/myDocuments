# ADR-003: 左サイドバーとフォルダツリーを前倒しし、設定を設定画面へ移す

## Status

Accepted（2026-11-02、承認者: プロジェクトオーナー）。仕様 §3.2（P1）の「フォルダ/ワークスペース」のうち、左サイドバーのフォルダツリーを MVP の内側へ前倒しする。3 回の Run（Run 8、9、10）に分けて実装する。

## Context

利用者がドッグフーディング（自分で使いながらの検証）を始め、VS Code のような左サイドバーのファイルツリーを求めた。あわせて次の 2 点が出た。

- 右側の外観パネルは、いまは使い道がない。外観の設定は設定画面へ移したい。
- 紙（本文面）の左右に見える背景の余白は、なくてよいかもしれない。ただし背景画像は、この余白でしか見えなくなる。

仕様 §3.2 は、フォルダ/ワークスペースを P1 に置いている。仕様の文書そのもの（`docs/spec/`）は書き換えない。この ADR が、仕様に対する変更として優先する。

## Decision

3 回の Run に分ける。

- Run 8（この ADR の対象）: 設定画面、紙の幅の切替、開閉できる左サイドバーの枠。ツリーも、フォルダを開く機能も作らない。
- Run 9: フォルダツリー（見る、開く）。
- Run 10: 作成、名前の変更、削除、ファイルシステムの変更の自動更新。

利用者の判断と、Run 8 の決め方は次のとおり。

- 右パネルをやめ、外観の設定をモーダルの設定画面へ移す。設定画面は「設定」の見出しの下に節を並べる構造で、いまの節は「外観」だけ。歯車の「設定」ボタンか Mod+, で開閉する。幕は薄くし、後ろの本文の変化が見えるようにする。
- 紙の既定を「窓いっぱい」（本文領域いっぱい）にする。設定の `surfaceWidth`（`fill` か `text`、既定 `fill`）で、従来の見た目（紙の幅を本文に合わせる、`text`）へ戻せる。1 行の長さは、どちらも本文の最大幅（`maxWidthPx`）で決まる。
- 左サイドバーを、フォルダツリーと合わせて仕様の P1 から前倒しする。開閉は上部バー左端のボタンか Mod+B で、状態は `sidebarOpen`（既定 false）として保存し、次回の起動で復元する。
- ツリーは全ファイルを表示し、開けないものは灰色にする。開けるのは Markdown 系と、`.txt`、`.text`。
- 作成、名前の変更、削除は、削除をゴミ箱へ移す形で行う（Run 10）。

Run 8 の配置の決め方:

- サイドバーの幅は 260px。開いているときは本文の領域を右へ押し出し、重ねない。本文の列と紙は、残りの領域の中央に置く。上部バー、下部バー、競合バー、トーストは、本文の領域に合わせて置く。
- 窓が狭く、押し出すと本文が最小幅を割るとき（本文の最大幅の最小値 320px + 左右の余白の最小 20px ずつ + サイドバー 260px = 620px 未満）は、本文を動かさず、サイドバーを本文の上に重ねる。重ねている間は上部バーの開閉ボタンが隠れるので、サイドバーの中に閉じるボタンを出す。Esc でも閉じる。
- サイドバーは、入力中の上下のバーの自動非表示では隠さない。利用者が明示的に開閉するもの、という扱い。
- Reduced Motion のときは、開閉にアニメーションを付けない。

## Consequences

- 右パネルのための配置（`panelLayout.ts`、`--md-panel-reserve`、`data-panel-shift`）は不要になり、消した。トーストと競合バーは、サイドバーを除いた本文の領域の中央を基準に置く。
- 外観の設定の項目の意味、文書の開く・保存・競合・草稿の挙動、書き心地は変えない。
- 紙の既定が変わるので、初回起動や保存済みの設定がない利用者には、見た目が変わる。保存済みの設定に `surfaceWidth` がなければ、既定（`fill`）になる。以前の見た目は設定で戻せる。
- 背景画像は、「窓いっぱい」では紙の透け具合（本文面の不透明度）でしか見えない。見せたいときは「本文に合わせる」にする。設定画面に、その旨の説明を置いた。
- Preferences は Rust 側では中身を解釈しない JSON なので、Rust 側の変更はない。
- 設定画面はモーダルなので、開いている間は Mod+B（サイドバーの開閉）を無視する。

## 判断を見直す条件

- 「窓いっぱい」の既定で、背景を楽しみにしていた利用者が戸惑うという声が出たとき。
- フォルダツリー（Run 9、10）を実際に使い、サイドバーの幅や重ねる条件を変えたくなったとき。

## 未検証

- Windows と Ubuntu 実機での表示。Playwright では、3 OS の navigator を偽装して確かめた。実機は未確認。
- Tauri 窓の操作（Mod+B、設定画面の操作）。窓への入力は送らない方針なので、起動時の設定（`sidebarOpen`、`surfaceWidth`）が反映された描画だけを撮影で確かめた。
- 実 IME の変換中の挙動。変換中のキーを模した Playwright の検証だけで、実機の IME は未確認。
