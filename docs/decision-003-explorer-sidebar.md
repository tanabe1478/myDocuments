# ADR-003: 左サイドバーとフォルダツリーを前倒しし、設定を設定画面へ移す

## Status

Accepted（2026-11-02、承認者: プロジェクトオーナー）。仕様 §3.2（P1）の「フォルダ/ワークスペース」のうち、左サイドバーのフォルダツリーを MVP の内側へ前倒しする。3 回の Run（Run 8、9、10）に分けて実装する。

## Context

利用者がドッグフーディング（自分で使いながらの検証）を始め、VS Code のような左サイドバーのファイルツリーを求めた。あわせて次の 2 点が出た。

- 右側の外観パネルは、いまは使い道がない。外観の設定は設定画面へ移したい。
- 紙（本文面）の左右に見える背景の余白は、なくてよいかもしれない。ただし背景画像は、この余白でしか見えなくなる。

仕様 §3.2 は、フォルダ/ワークスペースを P1 に置いている。仕様の文書そのもの（`docs/spec/`）は書き換えない。この ADR が、仕様に対する変更として優先する。

## Decision

3 回の Run に分ける。

- Run 8（この ADR の対象）: 設定画面、紙の幅の切替、開閉できる左サイドバーの枠。ツリーも、フォルダを開く機能も作らない。
- Run 9: フォルダツリー（見る、開く）。
- Run 10: 作成、名前の変更、削除、ファイルシステムの変更の自動更新。

利用者の判断と、Run 8 の決め方は次のとおり。

- 右パネルをやめ、外観の設定をモーダルの設定画面へ移す。設定画面は「設定」の見出しの下に節を並べる構造で、いまの節は「外観」だけ。歯車の「設定」ボタンか Mod+, で開閉する。幕は薄くし、後ろの本文の変化が見えるようにする。
- 外観の右パネルをやめた後、R13（ADR-005）で、外観とは別に、部品のパネル（アウトラインなど）のための右ペインを新しく設けた。
- 紙の既定を「窓いっぱい」（本文領域いっぱい）にする。設定の `surfaceWidth`（`fill` か `text`、既定 `fill`）で、従来の見た目（紙の幅を本文に合わせる、`text`）へ戻せる。1 行の長さは、どちらも本文の最大幅（`maxWidthPx`）で決まる。
- 左サイドバーを、フォルダツリーと合わせて仕様の P1 から前倒しする。開閉は上部バー左端のボタンか Mod+B で、状態は `sidebarOpen`（既定 false）として保存し、次回の起動で復元する。
- ツリーは全ファイルを表示し、開けないものは灰色にする。開けるのは Markdown 系と、`.txt`、`.text`。
- 作成、名前の変更、削除は、削除をゴミ箱へ移す形で行う（Run 10）。

Run 8 の配置の決め方:

- サイドバーの幅は 260px。開いているときは本文の領域を右へ押し出し、重ねない。本文の列と紙は、残りの領域の中央に置く。上部バー、下部バー、競合バー、トーストは、本文の領域に合わせて置く。
- 窓が狭く、押し出すと本文が最小幅を割るとき（本文の最大幅の最小値 320px + 左右の余白の最小 20px ずつ + サイドバー 260px = 620px 未満）は、本文を動かさず、サイドバーを本文の上に重ねる。重ねている間は上部バーの開閉ボタンが隠れるので、サイドバーの中に閉じるボタンを出す。Esc でも閉じる。
- サイドバーは、入力中の上下のバーの自動非表示では隠さない。利用者が明示的に開閉するもの、という扱い。
- Reduced Motion のときは、開閉にアニメーションを付けない。

## Run 9 で決めた細部（フォルダツリー: 見る、開く）

- 開けるファイルは、拡張子（大文字小文字を区別しない）が md、markdown、mdown、mkd、mdx、txt、text のもの。一覧は `src/document/fileKinds.ts` の 1 か所で、「開く」「保存」ダイアログの絞り込み（以前は md、markdown、mdx、txt）も同じ一覧から作る。それ以外のファイルも表示し、灰色にして、クリックや Enter では開かない（`aria-disabled`）。
- フォルダを選ぶ入口は、フォルダ未選択のときの「フォルダを開く」、選択後の「別のフォルダを開く」。開いたフォルダは session（`lastFolder`）に保存し、次回の起動で復元する。古い session.json（`lastFolder` なし）は未選択として読む。復元できない（なくなった、読めない）ときは、未選択の表示に戻し、トーストで短く知らせ、`lastFolder` を消す。外付けドライブが外れているだけの場合も消えるので、再度選び直す。（Run 10 で変更: 記録は消さず、再試行できる。下の Run 10 の節）
- 中身は展開したときに読む（遅延読み込み）。並びはフォルダが先、その中は名前の自然順（数字は数として、大文字小文字は区別しない）。名前がドットで始まる項目は出さない。再読み込みボタンは、開いているフォルダと展開中のフォルダを読み直し、展開状態を保つ。展開状態は保存しない。
- 1 つのフォルダの項目が 5000 件を超えるときは、並べ替えた後の先頭 5000 件と、末尾の「ほか N 件」の行（クリック不可）を出す。切り捨てはネイティブ側で行う。ネイティブ側の並べ替え（切り捨ての基準）は Rust の自然順、画面の並べ替えは `Intl.Collator`（日本語ロケール）で、全角・かなの細かい順序が違うことがある。5000 件の境目の項目だけが、その差の影響を受けうる。
- シンボリックリンク: フォルダへのリンクは「↪」の印を付けて表示し、展開しない（ループの防止）。ファイルへのリンクは通常のファイル。壊れたリンクなどは `other` で、開けない項目として灰色にする。
- ネイティブ側は `open_folder`（存在するフォルダか確かめ、canonicalize した結果を登録）と `list_folder`（登録済みのフォルダ自身か配下だけ。canonicalize してから成分ごとの前方一致で判定し、`..` やシンボリックリンクで外へ出るものは NotAllowed）の 2 つ。権限は `allow-open-folder` と `allow-list-folder` だけを足し、dialog の権限は既存の `dialog:allow-open` のまま。フォルダの中のファイルは、これまでどおり `open_document` で開く（ツリーが読めるのは名前と種類だけ）。
- ツリーから開くときは、「開く」と同じ流れ（未保存の変更の確認、草稿、外部変更の監視、前回の文書の記録）を使う。いま開いている文書と同じファイルを押しても何もしない（編集中の本文を捨てない）。開けたら、本文にフォーカスを移す。開いている文書のファイルは、ツリー上で強調する（`aria-current`、左の線、太字）。
- `.txt` と `.text` は、Markdown の装飾（見出しの大きさ・太字、記号の薄色、強調・リンク・コードの色、引用の線、コードフェンスの帯、ぶら下げインデント）を付けない素のテキストで表示する。フォーカスモードの段落は、空行だけで分ける（見出し、リスト、フェンスを特別扱いしない）。空行の高さ（段落間隔）は、Markdown の記法ではないので同じに効かせる。保存のバイト列（BOM、改行）の扱いは変えない。別名保存で拡張子が変わったら、表示も切り替わる。無題の文書と、上の一覧にない拡張子のファイルは Markdown として扱う。Tab / Shift+Tab のリスト・引用のインデントは、Markdown と同じまま（`.txt` でも `- ` で始まる行は字下げされる）。
- ツリーのアクセシビリティ: `role=tree` / `treeitem` / `group`、`aria-level`、`aria-expanded`、roving tabindex。キーは、上下で移動、右で展開（展開済みなら最初の子へ）、左で折りたたみ（折りたたみ済みなら親へ）、Enter と Space でフォルダの開閉または文書を開く、Home と End。開けない項目の灰色は、パネル上でライト 4.6 対 1、ダーク 4.6 対 1 のコントラスト。矢印の回転は Reduced Motion のときは動かさない。

## Run 10 で決めた細部（作成、名前の変更、ゴミ箱、外部の変更の自動反映）

- 範囲は、作成（ファイル・フォルダ）、名前の変更、ゴミ箱への移動、外部の変更の自動反映。移動（ドラッグ）、複製、貼り付けは作らない。（R15 で変更: 移動は作った。下の「移動（R15）」。複製は作らない）
- 入口は、見出し部の「新しいファイル」「新しいフォルダ」ボタン、ツリーの項目と空き領域の右クリックメニュー（Shift+F10 とメニューキーでも開く）、F2（名前の変更）、Delete と macOS の ⌘⌫（ゴミ箱）。作成先は、選択（フォーカス）中のフォルダ、ファイルならその親、何も選んでいなければルート。名前はツリーの中の入力欄で付け、Enter で確定、Esc で取り消し、フォーカスが外れたら有効な名前なら確定、空なら取り消す。IME の変換中の Enter では確定しない。
- 名前の規則は、Rust 側（`entries.rs` の `validate_name`）が正本で、画面（`names.ts`）に同じ規則がある。拒否するのは、空・空白だけ、`/` と `\`、`.` と `..`、ドットで始まる名前（ツリーに出なくなるため）、`<>:"|?*` と制御文字、末尾のドットと空白。OS によらず同じ規則にする（フォルダを別の OS へ持ち出しても困らないように）。拒否したら入力欄を残し、理由を直下に出す。ファイルは拡張子がなければ `.md` を足す（拡張子の判定は `fileKinds` の `extensionOf`）。大文字小文字だけ違う名前の衝突は、ファイルシステムが区別するかで決まるので、画面では判断せず、ネイティブ側の AlreadyExists を入力欄に出す。
- ネイティブ側は `create_file`、`create_folder`、`rename_entry`、`trash_entry`、`watch_folders` の 5 つ。どれも、親フォルダを canonicalize してから、開いたフォルダの配下かを調べる（登録外、`..`、シンボリックリンクで外へ出るものは NotAllowed）。操作は、canonicalize した親 + 名前の項目そのものに効かせ、シンボリックリンクはリンク自体を名前変更・ゴミ箱へ移す。開いたフォルダ（ルート）自身は、名前の変更もゴミ箱への移動もできない。作成は `create_new` / `create_dir` で、既存を上書きせず、新しい ErrorKind `AlreadyExists`（画面側は `already-exists`）にする。
- Windows は、同名のフォルダがある場所へ `create_new` でファイルを作ろうとすると、AlreadyExists ではなく PermissionDenied を返す（macOS と Linux は AlreadyExists）。作成（ファイルとフォルダ）で PermissionDenied が返ったときは、作ろうとした名前の項目が実際にあるか（リンクは辿らず）確かめ、あれば AlreadyExists に直す（`creation_error`）。無ければ権限の問題なので PermissionDenied のまま。名前の変更には使わない（大文字小文字だけの変更では、移し先に同じ項目が既にあるため）。この変換は単体テストで確かめ、Windows 実機での動作は CI の結果で確かめる。
- 名前の変更も、既存の別の項目を上書きしない（確認してから rename）。同じ項目の大文字小文字だけの変更は、ファイルシステムが区別しなくても通す（同じ項目かは、unix は inode、それ以外は canonicalize の一致で判断）。戻り値は新しいパスで、名前を変えた項目が登録済みの文書（または、それを含むフォルダ）なら、新しいパスも `KnownPaths` に登録する（古いパスの登録は残す）。
- 限界: 確認してから rename するまでの間に、別のプロセスが同じ名前の項目を作ると、unix の rename は黙って上書きする（Windows も同様）。親フォルダを確認した後に、別のプロセスがそれをシンボリックリンクに差し替える競合も防げない。どちらも、ほかのプロセスが同じフォルダを同時に書き換える場合に限る。ファイル名の Unicode 正規化（macOS の NFC と NFD）の違いも、同じ名前とは見ない。
- ゴミ箱は `trash` クレート 5.2.9。macOS は Finder を操作しない `NSFileManager` の方式（`DeleteMethod::NsFileManager`）を選ぶ。Finder の方式は、AppleScript でほかのアプリを操作するので、自動化の許可の確認が出ることがあり、音も鳴る。引き換えに、NSFileManager の方式は Finder の「戻す」（Put Back）が効かないことがある（クレートの説明にある macOS の既知の問題）。ゴミ箱の処理は関数の引数で差し替えられ、単体テストは差し替えたもので規則（渡す対象、ルートと登録外の拒否、リンク自体）を確かめる。
- 本物のゴミ箱に入れるテストは、環境変数 `IME_TEST_REAL_TRASH=1` のときだけ動く。手元では動かさない（ユーザーのゴミ箱にファイルが入るため）。CI の `cargo test (src-tauri)` だけが 3 OS で設定する。失敗したときは、OS のエラーを出力する（Linux のランナーでは、ゴミ箱の場所が使えないことがある。その場合は、この項目だけが落ちる）。
- 削除の前には、毎回、アプリ内の確認（alertdialog、既定のフォーカスはキャンセル）を出す。開いている文書、またはそれを含むフォルダを移したら、直後に外部変更の確認（`checkExternal`）を呼び、既存の「外部で消えた」の扱いに乗せる（未保存の変更がなければ削除の表示、あれば競合バー）。親フォルダごと移すと監視の通知が来ないことがあるので、通知は待たない。
- 開いている文書の名前の変更は、`DocumentController.renameEntry` が受け持つ。文書の監視を外し、名前を変え、新しいパスで監視し直す（古いパスの「消えた」通知で、削除扱いにしないため）。パス、前回の文書の記録、草稿のパスが新しいパスになる（未保存の変更があれば、草稿をすぐ書き直す）。本文、未保存の状態、undo 履歴、カーソル、外部変更の状態は変えない。名前の変更が失敗したら、古いパスのまま監視を戻す。ほかの文書の操作の実行中は、名前の変更を受け付けず、入力欄に理由を出す。
- 外部の変更の自動反映は、ルートと展開中のフォルダを 1 つずつ `NonRecursive` で監視し（`FolderWatcher`、イベント `folder-changed { path }`）、文書の監視とは別に持つ。項目の増減と名前の変更だけを知らせる（既存の項目の中身の書き換えは、一覧が変わらないので通常は知らせない。ただし macOS の FSEvents は、作られて数秒以内のファイルへの書き込みにも「作られた」の印を持ち越し、notify が Create として渡すため、その場合は知らせることがある。読み直しが 1 回増えるだけなので、抑え込むフィルタは足さない。実測: 作成の 3 秒後の書き込みは Create から届き、20 秒後は Modify だけ）。通知は既存の文書の監視と同じ `QUIET` / `MAX_WAIT` でまとめる。通知を受けたら、そのフォルダだけを読み直し、展開状態と選択を保つ。消えたフォルダは展開をやめる。展開や折りたたみのたびに、監視するフォルダの一覧を付け替える。監視するフォルダは 256 件までで、超えた分は監視しない（再読み込みボタンで読み直せる）。再帰の監視にしないのは、見えていない深いフォルダまで監視すると、大きなフォルダで監視の数と負荷が増えるため。
- N2（Run 9 の注記）: 起動時に前回のフォルダを開けないとき、session の `lastFolder` を消さない（外付けドライブが外れているだけのことがある）。サイドバーの空の状態に、「前回のフォルダ「名前」を開けませんでした（理由）」「再試行」「フォルダを開く」を出す。開けるようになった後の再試行でツリーが出る。別のフォルダを開けたら、その記録で上書きする。Run 9 の「復元できないときは `lastFolder` を消す」を、この Run で置き換える。
- CI は `actions/checkout` と `actions/setup-node` を v7 に上げた。そのほかの設定は変えていない。

## 移動（R15）

項目（ファイルとフォルダ）を、ツリーの中で別のフォルダへ移す。Run 10 の「移動は作らない」を、この節で置き換える。

- 入口は 3 つ。ドラッグアンドドロップ、キーボードの切り取りと貼り付け（ツリーの項目にフォーカスがあるとき。macOS は ⌘X と ⌘V、ほかは Ctrl+X と Ctrl+V）、右クリックのメニューの「切り取り」と「貼り付け」（本体の項目の並びは、新しいファイル、新しいフォルダ、名前を変更、切り取り、貼り付け、ゴミ箱に移動。空き領域のメニューは、新しいファイル、新しいフォルダ、貼り付け。「貼り付け」は切り取りの印があるときだけ選べる。aria-disabled で、フォーカスは受ける）。
- 移し先の規則は、ドラッグの落とし先も貼り付けも同じ。フォルダの行ならその中、ファイルの行ならその親、補足の行（空のフォルダ、読み込み中）ならその所属のフォルダ、行のない所（ドラッグではツリーの空いている所）ならルート。フォルダへのシンボリックリンクの行は、展開できず中身を持たないので、ファイルの行と同じに扱い、その親へ移す。移せないのは、同じフォルダ（何も起きない。切り取りの印は残る）、フォルダを自分自身かその中のフォルダへ（貼り付けでは「フォルダは、自分自身の中には移せません。」と知らせる。ドラッグでは、そもそも落とせない先にする）。
- ネイティブ側は `move_entry(path, dest_dir, conflict)`（conflict は `fail`、`replace`、`keep-both`）。戻り値は移した後のパスで、渡された `dest_dir` の形 + 最終の名前。項目は `resolve_item`、移し先は `resolve_dir` と同じ規則で確かめる（開いたフォルダの配下、canonicalize、`..` とリンクで外へ出るものは NotAllowed）。開いたフォルダ（ルート）自身は移さない（NotAllowed）。項目の親と移し先が同じなら、何もせず元のパスを返す。フォルダを自分自身かその中へ移そうとしたら NotAllowed（InvalidInput にしなかったのは、画面の文言が「この場所では操作できません」になり、名前の問題と混ざらないため）。シンボリックリンクはリンク自体として動かし、リンク先の中かどうかでは判定しない（リンクを、リンク先のフォルダの中へ移すことはできる）。
- 同じ名前の判定は、移し先 + 名前の項目の有無（`symlink_metadata`。リンクは辿らない）。ファイルシステムが大文字小文字を区別しなければ、違う大文字小文字の項目も同じ名前として見つかる。`fail` は AlreadyExists。`replace` は、既存の項目（フォルダなら中身ごと 1 つの項目）をゴミ箱へ移してから rename する。ゴミ箱の処理は `trash_entry` と同じく関数の引数で、ゴミ箱へ移せなければ移さない（Io）。置き換えられないのは、移す項目が既存の項目の中にあるとき（既存の項目が、移す項目の祖先。同じ名前のフォルダの中のフォルダを、その外へ出す場合など）と、既存の項目が登録した開いたフォルダのとき（どちらも NotAllowed）。`keep-both` は、`名前 2.md`、`名前 3.md` のように、拡張子の前に「 2」「 3」…を付けた、空いている最初の名前で移す。拡張子がない名前と、フォルダ（名前にドットがあっても）は末尾に付ける（`README 2`、`notes.v1 2`）。拡張子は最後のドットから（`a.tar.gz` は `a.tar 2.gz`）。ドットで始まる名前の先頭のドットは、拡張子の区切りとして扱わない。上限は 999 で、超えたら AlreadyExists。付けた名前も `validate_name` を通す。
- rename の失敗（別のディスクなど）は、コピーと削除で代用せず、そのままエラーで返す。`replace` で、ゴミ箱へ移した後に rename が失敗したときは、既存の項目はゴミ箱に入ったままで、移す項目は元の場所に残る。
- 成功したら、`rename_entry` と同じく、移した項目が登録済みの文書（またはそれを含むフォルダ）なら、新しいパスも `KnownPaths` に登録する（古いパスの登録は残す）。
- 画面側（`ExplorerController.move`）は、まず `fail` で移し、AlreadyExists が返ったら確認のダイアログを出して、選ばれた扱いでやり直す。ツリーに読み込み済みの中身には頼らない（読み込んでいない、5000 件の上限の外、ほかのプロセスが作った、のどれでも確実に気づける）。確認の文言と、移す項目と既存の項目の種類が違うときの一言のために、移し先を一度読み直して既存の項目を探す（見つからなければ、移す項目と同じ種類として扱う）。
- 確認のダイアログ（alertdialog）は毎回出す。「“名前” という名前の項目が “移し先のフォルダの名前” にすでにあります。」（移し先がルートなら、ルートのフォルダの名前）。選択肢は、置き換える（既存の項目はゴミ箱へ移ると明記）、両方とも残す（既定のフォーカス）、中止（Esc もこれ）。Tab はダイアログの中で回り、閉じたあとはフォーカスをツリーへ戻す。中止では何も変えず、切り取りの印も残す。
- 置き換えを選べない条件は 2 つ。既存の項目が、開いている文書そのもの、またはそれを含むフォルダ（文書を消すことになる。`isDocumentInside`）。移す項目が既存の項目の中にある（ネイティブ側の NotAllowed と同じ判断を、画面でも先に見る）。選べないときは、「置き換える」を aria-disabled にして、理由を直下に出す（ボタンの aria-describedby から読める）。ほかの 2 つ（両方とも残す、中止）は選べる。ネイティブ側が守るのは、2 つ目と、既存の項目が登録した開いたフォルダのとき（ネイティブ側は、エディタが開いている文書を知らないので、1 つ目は画面側だけの判断）。
- 開いている文書への追従は、名前の変更と同じ経路（`DocumentController.renameEntry`）を使う。文書の監視を外し、移し、新しいパスで監視し直す。パス、前回の文書の記録、草稿のパスが新しいパスになり、本文、未保存の状態、undo 履歴、カーソルは変えない。保存は新しいパスへ書かれる。移動に失敗したら、古いパスのまま監視を戻す。ほかの文書の操作の実行中は、移さずに理由を知らせる。
- 移した後の状態: 展開状態と選択は新しいパスへ引き継ぎ（移したフォルダの中の読み込み済みの中身は、パスが古いので捨てて読み直す）、移し先のフォルダを開き、移した項目を選んでフォーカスする。移し元と移し先を読み直す。置き換えたフォルダの中について、ツリーが知っていたことは捨てる。失敗はトースト（「移動できませんでした。」に、名前の変更などと同じ言い回しの理由）。
- ドラッグは HTML5 のドラッグアンドドロップ（`tauri.conf.json` の `dragDropEnabled` は既に false で、Windows でも使える。変えていない）。ファイルとフォルダの行を `draggable` にする（補足の行と、名前の入力欄が開いている間は引かない）。dataTransfer に入れるのは、ツリーの項目であることを示す独自の型 `application/x-mde-tree-item` と値 `move` だけ（パスも名前も、`text/plain` も入れない）。何を引いているかは、ツリーの中の状態で持つ。この状態がないドラッグ（Finder などの外からのもの）は受け付けず、`dropEffect` を none にする。落とせない先も none にして、強調しない。引くときの画像は、展開したフォルダでも、その行だけにする。
- ドラッグ中の強調は、色だけに頼らない。落とせるフォルダの行に 2px の実線の枠と背景、ルートに落とすときはツリー全体に 2px の破線の枠、引いている行は薄い色と斜体。枠の色は背景に対して 3 対 1 以上、文字は 4.5 対 1 以上（ライトとダークの両方で e2e が計算する）。強調には transition も animation も付けない（Reduced Motion でも同じ）。閉じたフォルダの上で 700ms 止まると開く（引いている項目自身とその中のフォルダは開かない）。ツリーの領域の上下の端から 28px 以内に入ると、位置に応じた速さ（最大 14px / 16ms）でスクロールする。Esc で取り消せる（ブラウザの既定。何も移らない）。
- 切り取りの印は、アプリの中の状態だけ（`ExplorerState.cut`）。`navigator.clipboard` にも OS のクリップボードにも、書かず、読まない（キーの処理は `preventDefault` する。キーを経由せずに届いた `cut` と `paste` のイベントも、項目の行にフォーカスがあるときはツリーの操作にして、クリップボードの中身は読まない）。印の付いた行は、薄い色（開けないファイルと同じ灰色。パネル上で 4.6 対 1）、斜体、行の下の破線で示し、名前（aria-label）に「（切り取り済み）」を足す。Esc で外れる。貼り付けで移したら外れる。移さなかったとき（同じフォルダ、中止、失敗）は残る。印の付いた項目が一覧から消えたら（ゴミ箱、外部の削除、名前の変更の前の名前）、別のフォルダを開いたら、外れる。一覧が読み込み済みでない、件数の上限で一部しか出していないときは、確かめられないので残す。名前を変えた、または移したフォルダの中の印は、新しいパスへ引き継ぐ。
- キーは、項目の行（`role=treeitem`）にフォーカスがあるときだけ。名前の入力欄の中のキーは、今までどおり文字の切り取りと貼り付けで、ツリーの操作にしない。IME の変換中（`isComposing`）は対象にしない。本文（CodeMirror）の ⌘X と ⌘V は変えない。
- アプリのログ（ADR-007）への記録は、移動の失敗だけ。source は `explorer`、event は `move-failed`、data は操作の名前（`move`）、`conflict` の値、エラーの種類（`error` と `kind`）。パスと名前とメッセージは書かない。`ExplorerController` はログ基盤を直接は使わず、`onMoveFailed` を App が受ける（ログ基盤を読み込んでよいファイルの一覧を変えないため）。
- やらないこと: 外（Finder など）からの取り込み、複数の項目をまとめて移す、別のディスクへの移動（rename が失敗するのでエラーにする。コピーと削除では代用しない）、コピー（複製、Option を押しながらのドラッグ）、移動の取り消し（元に戻す）。
- 限界: 同じ名前を確かめてから rename するまでの間に、別のプロセスが同じ名前の項目を作ると、unix の rename は黙って上書きする（Windows も同様）。防ぐには、rename を排他的に行う仕組み（macOS の `renamex_np`、Linux の `renameat2` など、OS ごとの呼び出し）の依存の追加が要るので見送った。名前の変更の限界（Run 10）と同じ。親フォルダの差し替えの競合、ファイル名の Unicode 正規化の違いも同じ。移し先の既存の項目の探索は、読み直した一覧（5000 件の上限まで）から行うので、上限の外にある同じ名前の項目は、種類が移す項目と同じだと仮定した確認になる（rename の判断はネイティブ側が持つので、上書きはされない）。

## Consequences

- 右パネルのための配置（`panelLayout.ts`、`--md-panel-reserve`、`data-panel-shift`）は不要になり、消した。トーストと競合バーは、サイドバーを除いた本文の領域の中央を基準に置く。
- 外観の設定の項目の意味、文書の開く・保存・競合・草稿の挙動、書き心地は変えない。
- 紙の既定が変わるので、初回起動や保存済みの設定がない利用者には、見た目が変わる。保存済みの設定に `surfaceWidth` がなければ、既定（`fill`）になる。以前の見た目は設定で戻せる。
- 背景画像は、「窓いっぱい」では紙の透け具合（本文面の不透明度）でしか見えない。見せたいときは「本文に合わせる」にする。設定画面に、その旨の説明を置いた。
- Preferences は Rust 側では中身を解釈しない JSON なので、Rust 側の変更はない（Run 9 で session だけ `lastFolder` が増えた）。
- 設定画面はモーダルなので、開いている間は Mod+B（サイドバーの開閉）を無視する。

## 判断を見直す条件

- 「窓いっぱい」の既定で、背景を楽しみにしていた利用者が戸惑うという声が出たとき。
- フォルダツリー（Run 9、10）を実際に使い、サイドバーの幅や重ねる条件を変えたくなったとき。
