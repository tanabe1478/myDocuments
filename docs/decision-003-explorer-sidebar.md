# ADR-003: 左サイドバーとフォルダツリーを前倒しし、設定を設定画面へ移す

## Status

Accepted（2026-11-02、承認者: プロジェクトオーナー）。仕様 §3.2（P1）の「フォルダ/ワークスペース」のうち、左サイドバーのフォルダツリーを MVP の内側へ前倒しする。3 回の Run（Run 8、9、10）に分けて実装する。

## Context

利用者がドッグフーディング（自分で使いながらの検証）を始め、VS Code のような左サイドバーのファイルツリーを求めた。あわせて次の 2 点が出た。

- 右側の外観パネルは、いまは使い道がない。外観の設定は設定画面へ移したい。
- 紙（本文面）の左右に見える背景の余白は、なくてよいかもしれない。ただし背景画像は、この余白でしか見えなくなる。

仕様 §3.2 は、フォルダ/ワークスペースを P1 に置いている。仕様の文書そのもの（`docs/spec/`）は書き換えない。この ADR が、仕様に対する変更として優先する。

## Decision

3 回の Run に分ける。

- Run 8（この ADR の対象）: 設定画面、紙の幅の切替、開閉できる左サイドバーの枠。ツリーも、フォルダを開く機能も作らない。
- Run 9: フォルダツリー（見る、開く）。
- Run 10: 作成、名前の変更、削除、ファイルシステムの変更の自動更新。

利用者の判断と、Run 8 の決め方は次のとおり。

- 右パネルをやめ、外観の設定をモーダルの設定画面へ移す。設定画面は「設定」の見出しの下に節を並べる構造で、いまの節は「外観」だけ。歯車の「設定」ボタンか Mod+, で開閉する。幕は薄くし、後ろの本文の変化が見えるようにする。
- 紙の既定を「窓いっぱい」（本文領域いっぱい）にする。設定の `surfaceWidth`（`fill` か `text`、既定 `fill`）で、従来の見た目（紙の幅を本文に合わせる、`text`）へ戻せる。1 行の長さは、どちらも本文の最大幅（`maxWidthPx`）で決まる。
- 左サイドバーを、フォルダツリーと合わせて仕様の P1 から前倒しする。開閉は上部バー左端のボタンか Mod+B で、状態は `sidebarOpen`（既定 false）として保存し、次回の起動で復元する。
- ツリーは全ファイルを表示し、開けないものは灰色にする。開けるのは Markdown 系と、`.txt`、`.text`。
- 作成、名前の変更、削除は、削除をゴミ箱へ移す形で行う（Run 10）。

Run 8 の配置の決め方:

- サイドバーの幅は 260px。開いているときは本文の領域を右へ押し出し、重ねない。本文の列と紙は、残りの領域の中央に置く。上部バー、下部バー、競合バー、トーストは、本文の領域に合わせて置く。
- 窓が狭く、押し出すと本文が最小幅を割るとき（本文の最大幅の最小値 320px + 左右の余白の最小 20px ずつ + サイドバー 260px = 620px 未満）は、本文を動かさず、サイドバーを本文の上に重ねる。重ねている間は上部バーの開閉ボタンが隠れるので、サイドバーの中に閉じるボタンを出す。Esc でも閉じる。
- サイドバーは、入力中の上下のバーの自動非表示では隠さない。利用者が明示的に開閉するもの、という扱い。
- Reduced Motion のときは、開閉にアニメーションを付けない。

## Run 9 で決めた細部（フォルダツリー: 見る、開く）

- 開けるファイルは、拡張子（大文字小文字を区別しない）が md、markdown、mdown、mkd、mdx、txt、text のもの。一覧は `src/document/fileKinds.ts` の 1 か所で、「開く」「保存」ダイアログの絞り込み（以前は md、markdown、mdx、txt）も同じ一覧から作る。それ以外のファイルも表示し、灰色にして、クリックや Enter では開かない（`aria-disabled`）。
- フォルダを選ぶ入口は、フォルダ未選択のときの「フォルダを開く」、選択後の「別のフォルダを開く」。開いたフォルダは session（`lastFolder`）に保存し、次回の起動で復元する。古い session.json（`lastFolder` なし）は未選択として読む。復元できない（なくなった、読めない）ときは、未選択の表示に戻し、トーストで短く知らせ、`lastFolder` を消す。外付けドライブが外れているだけの場合も消えるので、再度選び直す。
- 中身は展開したときに読む（遅延読み込み）。並びはフォルダが先、その中は名前の自然順（数字は数として、大文字小文字は区別しない）。名前がドットで始まる項目は出さない。再読み込みボタンは、開いているフォルダと展開中のフォルダを読み直し、展開状態を保つ。展開状態は保存しない。
- 1 つのフォルダの項目が 5000 件を超えるときは、並べ替えた後の先頭 5000 件と、末尾の「ほか N 件」の行（クリック不可）を出す。切り捨てはネイティブ側で行う。ネイティブ側の並べ替え（切り捨ての基準）は Rust の自然順、画面の並べ替えは `Intl.Collator`（日本語ロケール）で、全角・かなの細かい順序が違うことがある。5000 件の境目の項目だけが、その差の影響を受けうる。
- シンボリックリンク: フォルダへのリンクは「↪」の印を付けて表示し、展開しない（ループの防止）。ファイルへのリンクは通常のファイル。壊れたリンクなどは `other` で、開けない項目として灰色にする。
- ネイティブ側は `open_folder`（存在するフォルダか確かめ、canonicalize した結果を登録）と `list_folder`（登録済みのフォルダ自身か配下だけ。canonicalize してから成分ごとの前方一致で判定し、`..` やシンボリックリンクで外へ出るものは NotAllowed）の 2 つ。権限は `allow-open-folder` と `allow-list-folder` だけを足し、dialog の権限は既存の `dialog:allow-open` のまま。フォルダの中のファイルは、これまでどおり `open_document` で開く（ツリーが読めるのは名前と種類だけ）。
- ツリーから開くときは、「開く」と同じ流れ（未保存の変更の確認、草稿、外部変更の監視、前回の文書の記録）を使う。いま開いている文書と同じファイルを押しても何もしない（編集中の本文を捨てない）。開けたら、本文にフォーカスを移す。開いている文書のファイルは、ツリー上で強調する（`aria-current`、左の線、太字）。
- `.txt` と `.text` は、Markdown の装飾（見出しの大きさ・太字、記号の薄色、強調・リンク・コードの色、引用の線、コードフェンスの帯、ぶら下げインデント）を付けない素のテキストで表示する。フォーカスモードの段落は、空行だけで分ける（見出し、リスト、フェンスを特別扱いしない）。空行の高さ（段落間隔）は、Markdown の記法ではないので同じに効かせる。保存のバイト列（BOM、改行）の扱いは変えない。別名保存で拡張子が変わったら、表示も切り替わる。無題の文書と、上の一覧にない拡張子のファイルは Markdown として扱う。Tab / Shift+Tab のリスト・引用のインデントは、Markdown と同じまま（`.txt` でも `- ` で始まる行は字下げされる）。
- ツリーのアクセシビリティ: `role=tree` / `treeitem` / `group`、`aria-level`、`aria-expanded`、roving tabindex。キーは、上下で移動、右で展開（展開済みなら最初の子へ）、左で折りたたみ（折りたたみ済みなら親へ）、Enter と Space でフォルダの開閉または文書を開く、Home と End。開けない項目の灰色は、パネル上でライト 4.6 対 1、ダーク 4.6 対 1 のコントラスト。矢印の回転は Reduced Motion のときは動かさない。

## Consequences

- 右パネルのための配置（`panelLayout.ts`、`--md-panel-reserve`、`data-panel-shift`）は不要になり、消した。トーストと競合バーは、サイドバーを除いた本文の領域の中央を基準に置く。
- 外観の設定の項目の意味、文書の開く・保存・競合・草稿の挙動、書き心地は変えない。
- 紙の既定が変わるので、初回起動や保存済みの設定がない利用者には、見た目が変わる。保存済みの設定に `surfaceWidth` がなければ、既定（`fill`）になる。以前の見た目は設定で戻せる。
- 背景画像は、「窓いっぱい」では紙の透け具合（本文面の不透明度）でしか見えない。見せたいときは「本文に合わせる」にする。設定画面に、その旨の説明を置いた。
- Preferences は Rust 側では中身を解釈しない JSON なので、Rust 側の変更はない（Run 9 で session だけ `lastFolder` が増えた）。
- 設定画面はモーダルなので、開いている間は Mod+B（サイドバーの開閉）を無視する。

## 判断を見直す条件

- 「窓いっぱい」の既定で、背景を楽しみにしていた利用者が戸惑うという声が出たとき。
- フォルダツリー（Run 9、10）を実際に使い、サイドバーの幅や重ねる条件を変えたくなったとき。

## 未検証

- Windows と Ubuntu 実機での表示。Playwright では、3 OS の navigator を偽装して確かめた。実機は未確認。
- Tauri 窓の操作（Mod+B、設定画面の操作、ツリーの展開・クリック）。Run 9 では、実際のファイルシステムからのツリーの復元だけを撮影で確かめた。窓への入力は送らない方針なので、起動時の設定（`sidebarOpen`、`surfaceWidth`）が反映された描画だけを撮影で確かめた。
- 実 IME の変換中の挙動。変換中のキーを模した Playwright の検証だけで、実機の IME は未確認。
- ネイティブのフォルダ選択ダイアログ。メモリ bridge では seed の `folderPath` が戻り値の代わり。
- Windows の隠し属性（ドットで始まらない隠しファイル）。判定は名前がドットで始まるかだけ。
