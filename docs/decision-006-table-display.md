# ADR-006: Markdown の表を、カーソルが表の外にあるとき表の形で表示する（ADR-004 の延長）

## Status

Accepted（2026-11-09、承認者: プロジェクトオーナー）。ADR-004（カーソルのない行で記号を隠す）を、表に広げる。仕様 §5.2（標準はソースの編集。表示は表示上のもので、本文に不要な自動変更を加えない。ソースの安定を犠牲にして WYSIWYG を入れない）と ED-09（表を損なわない）に従う。仕様の文書そのもの（`docs/spec/`）は書き換えない。

## Context

これまで、Markdown の表（GFM のパイプの表）には専用の表示がなく、`|` と区切りの行が、本文と同じ比例フォントの普通の文字として並んでいた。列がそろわないので、表として読みづらい。

他のエディタが表をどう扱うかを、各製品の文書で調べた（親が文書を読んだ結果で、アプリは動かしていない）。

- 表のまま直接編集する型。Typora は、ツールバーで大きさ・配置・削除を行い、Cmd/Ctrl+Enter で行を足し、行と列をドラッグで動かす（https://support.typora.io/Table-Editing 、https://support.typora.io/Markdown-Reference/ ）。Obsidian は 1.5 以降、右クリックで行と列の追加・削除・並べ替え・移動・配置を行い、1.5.8 で入力中に原文の列を自動でそろえる（https://obsidian.md/help/Editing+and+formatting/Advanced+formatting+syntax 、https://obsidian.md/de/changelog/2024-02-22-desktop-v1.5.8/ ）。Bear 2 は、セルのメニューで行と列を足す（https://bear.app/faq/how-to-use-tables-in-bear/ ）。
- 表で見せ、カーソルのあるセルだけ原文にする型。Zettlr 4.0 は、Tab / Shift+Tab でセルを移り、最後のセルの Tab で行を足す。`|` をそろえる整形は明示のコマンドで、等幅フォントが要る。パイプの表だけを扱う（https://docs.zettlr.com/en/editor/tables/ 、https://www.zettlr.com/post/zettlr-400-released ）。
- 原文のまま、整形を補助する型。iA Writer は、メニューで表のセルを作る。Windows 版は Format → Table → Reformat（https://ia.net/writer/support/basics/markdown-guide ）。VS Code の拡張と mte-kernel は、Tab でセルを移り、そのときに整形する（https://npmjs.com/package/@susisu/mte-kernel 、https://github.com/philipparndt/vscode-markdown-tables ）。
- どの型でも、保存はパイプの表。セルの中の改行とセルの結合はできない。Typora が保存のときに `|` をそろえるかは、文書になく、未確認。

利用者は、表の形で表示し、原文の中では Tab でセルを移る方針を選んだ。直接編集の型は、保存のたびに原文を書き換えうるので、仕様 §5.2 の「本文に不要な自動の変更を加えない」と合わない。

## Decision

### 1. 表の形で表示する

設定「記号の表示」が既定の「カーソルのある行だけ」（cursorLine）のとき、親が文書（Document）の表（トップレベルの表）を、選択が触れていない間、表の形で表示する。

- 触れていない、とは、選択のどの範囲も、表の範囲に触れないこと。表の範囲は、最初の行の行頭から、最後の行の行末まで。端の一致（表の頭や末尾にカーソルがある）も、触れているとする。触れたら、その表だけが原文に戻る。ほかの表は表示のまま。
- 見出しの行は見出しのセル（th）、本文の行は普通のセル（td）。区切りの行は表示しない。列の配置は、区切りの行の `:` に従う（`:--` 左、`:-:` 中央、`--:` 右、なしは左）。
- 列の数は見出しの行のセルの数。本文の行で足りないセルは空、余るセルは表示しない（GFM と同じ）。空のセルも列に数える。セルの境界は、構文木の行の `|`（TableDelimiter）の位置から求める。構文木の TableCell は、空のセルには出ないため。
- セルの中の `\|` は `|` と表示する。インラインコードの中の `|` も、GFM の仕様どおりセルの区切りになる。
- セルの中の強調、太字、取り消し線、インラインコード、インラインのリンク（文字だけ。リンクの色と下線）、自動リンク `<https://...>`（`<` `>` を除く）、GFM の裸の URL は、ほかの行で記号を隠したときと同じ見た目にする。同じ CSS 変数（`--md-color-link`、`--md-color-code`、`--md-color-muted` など）を使い、e2e で、同じ文書の隠した行と、computed style（太さ、斜体、線、色、フォント、サイズ）が一致することを確かめる。画像、参照リンク、HTML、エスケープ（`\*` など）は、原文の文字のまま。
- DOM は createElement と textContent だけで組み立てる。`innerHTML`、`insertAdjacentHTML` などは使わず、文書に書かれた `<script>` や `<img onerror>` は文字として表示されて、動かない（単体テストと e2e で確かめる。単体テストは、ソースにそれらの API がないことも検査する）。
- 表の幅は本文の幅を超えない。表は内容に合わせた幅で、セルの中で折り返し（`overflow-wrap: anywhere`）、横スクロールは出ない。色は CSS 変数で、明暗のテーマに追従する。
- 原文のまま（これまでと同じ）にするもの: 設定が「常に表示」のとき、素のテキスト（.txt、.text）、引用やリストの中の表、frontmatter の中、構文木の解析がまだ届いていない範囲（表が解析済みの範囲の端に触れているものも含む）。原文の表の中では、ADR-004 の行ごとの記号の隠し方が、今のまま働く。

実装は、表全体を 1 つのブロック（`Decoration.replace` の `block: true`）に置き換える。行をまたぐ置き換えは、CodeMirror では ViewPlugin から出せず、state 側から出す必要があるので、StateField（`tableDisplay.ts`）を使う。表の一覧は、構文木の最上位の子を見るだけで作る。選択だけが変わったときは、触れている表が変わったときにだけ、装飾を作り直す（表の一覧と、表ごとの装飾は使い回す）。原文が同じ表の DOM は、位置がずれても使い回す（`eq`）。

### 2. 表への出入り

- 表示中の表を、修飾キーなしの左クリックすると、クリックしたセルの中身の末尾にカーソルを置く（その結果、表は原文に戻る）。セルの外（枠や余白）なら、一番近いセル。座標から決められなければ、表の頭。⌘/Ctrl+クリックと Alt+クリックも同じ扱いで、リンクは開かない。Shift+クリックは、選択の anchor を保ったまま、head をその位置まで伸ばす。右クリックと中クリックは何もしない。空のセルの行き先は、Tab の移動と同じ（中身の頭）。クリックの transaction は、通常の本文のクリックと同じ `select.pointer` で、本文は変えない（タイプライターモードは、ポインタでの選択では中央へ合わせ直さない。ADR-004 の方針と同じ）。
- 上下の矢印キー（mac は Ctrl-n / Ctrl-p を含む。Shift 付きも）で、表示中の表の上と下の行から表に入る。下へなら見出しの行、上へなら最後の行へ、桁を保って入り、表は原文になる。標準の上下移動は、表示中のブロックを飛ばすので、標準より先に受ける。折り返した行の途中の移動は、標準のまま。
- 左右の矢印キー、検索（一致への移動）、ドラッグ、Undo などで選択が表に触れたときも、表は原文になる。選択が表から出ると、表示に戻る。
- IME の変換中（compositionStarted）は、表示と原文の切り替えを、ほかの表も含めて保留する。変換の開始と終了を state に effect で伝え（終了は、ADR-004 と同じ `AFTER_COMPOSITION_MS` の待ち）、保留中は、表示中の表の位置だけを本文の変化に追従させる。変換中に、ほかの行や表の DOM を作り直さない（e2e で、表の DOM 要素が同一のままであることを確かめる）。

### 3. 本文を変えない

表示の切り替え、出入り、Tab の移動は、選択だけを変える。docChanged の transaction を出さず、Undo の履歴に何も積まない。保存したバイト列が元と同じこと、コピーした文字列が原文であることを、e2e で確かめる（BOM と CRLF の文書を含む）。

### 4. Tab でセルを移る

設定「記号の表示」によらず（「常に表示」でも）効く。

- 条件: 選択がすべて空で、カーソルがトップレベルの表の中（原文）にあるとき。IME の変換中は、何もしない（キーは受ける）。
- Tab は次のセルの中身の頭、Shift+Tab は前のセルの中身の頭へ、カーソルを移す。区切りの行は飛ばし、行をまたぐ。列の数は、各行の実際のセル（空のセルを含む）で数える。カーソルがセルの中にあれば、そのセルの前後のセル。セルの外（行頭の `|` の前、行末の `|` の後ろ、区切りの行）なら、位置の後ろ（前）で最初（最後）のセル。
- 中身の頭は、セルの左の `|` の後ろの空白を飛ばした位置。空のセルは、左の `|` の直後に空白があれば、その 1 つ後ろ（次の `|` を越えない）。なければ `|` の直後。外側の `|` を書かない行（`a | b`）の最初のセルは、行頭から数える。
- 最初のセルで Shift+Tab、最後のセルで Tab は、動かない。キーは受ける（フォーカスは動かさず、文字も入れない）。
- Esc の直後の Tab は、表の中でも、これまでどおり本文の外へフォーカスを移す。表の外、範囲を選んでいるとき、引用やリストの中の表は、今の字下げのまま。

Tab は、本体の字下げのキー割り当て（`indentKeymap.ts`）が受ける。Esc の直後の判断をそこに 1 か所で持つため、キー割り当てを部品側に足さず、本体が、Esc の直後でなければ、plugin-api の `tabHandlers`（部品が先に受ける入口）を順に呼び、true を返したものがあれば字下げしない形にした。

### 5. ほかの機能との組み合わせ

- タイプライターモード: 表への出入りも、ほかの選択の移動と同じで、キー操作の後に、カーソルの行が中央に戻る（e2e で、既存のタイプライターの検査と同じ ±6px）。ポインタ（クリック）で入ったときは、中央へ合わせ直さない。
- フォーカスモード: 表示中の表は、カーソルの段落でなければ弱く表示される。行の装飾は、置き換えた表示の中には届かないので、plugin-api に共通の約束を足した。弱く表示する部品（フォーカスモード）は `dimExemptLines`（いま弱くしない行の範囲）を提供し、表示を置き換える部品（Markdown の見た目）は、それを読んで自分の要素に `DIMMED_BLOCK_CLASS` を付ける（見た目の不透明度と遷移は、フォーカスモードが決める）。部品どうしは、互いの内部を import せず、DOM の class を共有もしない（ADR-005 と `architecture.test.ts` の約束）。
- 通常のモード: 表に出入りしたとき、カーソルの行は画面の外へ出ない（e2e で確かめる）。
- 読む位置の保存、アウトライン、検索は、これまでどおり動く（既存の e2e が通る）。

## やらないこと

セルへの直接の書き込み、入力中の自動整形と `|` をそろえるコマンド、列幅の調整、行や列のドラッグ、並べ替え、セル内の改行、セルの結合、表示中の表のリンクの ⌘/Ctrl+クリックで開くこと、行や表を足すキー操作、新しい設定項目（表示は、既存の「記号の表示」に従う）。

## Consequences

- 既定の見た目が変わる。表を原文で見たい利用者は、設定で「常に表示」にする（表のセルの移動の Tab は、そのままできる）。
- 部品の拡張のうち、Markdown の見た目が、StateField と、本体への入口（`tabHandlers`）を使うようになった。plugin-api に、`tabHandlers`、`dimExemptLines`、`isDimmedBlock`、`DIMMED_BLOCK_CLASS` が増えた。
- 性能（Chromium、Apple M5 の macOS、メモリ bridge の e2e ビルド。変更前は d534236。ビルドごとに新しいページで、交互に 5 ラウンド、各 100 回）: 表 200 個（各 20 行、3 列。4602 行）の文書で、キーを押してから CodeMirror の更新通知までの中央値は、カーソルの下への移動 0.7ms（変更前 0.7ms）、上への移動 0.7ms（0.7ms）、表の外での 1 文字の入力 1.1ms（0.9ms）、表の中での 1 文字の入力 0.9ms（0.9ms）。表のない約 1MB（35086 行）の文書の 1 文字の入力は 2.4ms（2.3ms）。doc の変更のたびに表の一覧を作り直すが、構文木の最上位を配列のまま読むので、表のない長い文書でも、ほとんど増えない（ノードの参照を作る走査では、1MB の入力が 2.5ms から 3.2ms に増えたので、この形にした）。

## 限界

- 実機（Tauri の窓、WKWebView）と、実 IME（Microsoft IME、macOS の日本語入力、Mozc）では、未確認。Playwright の Chromium と、CDP による変換の模擬だけで確かめた。Windows と Ubuntu の実機も未確認。
- 表に出入りすると、表の高さが変わり、下の行が動く。表示中の表と原文の高さは、一致しない。描画する前の表の高さは見積もりで、実際の高さと違うため、遠くへのスクロール中に、スクロールバーの長さが少し変わることがある。
- 表示中の表は、中の文字を選んだり、一部だけコピーしたりできない（クリックすると原文になるので、原文で選ぶ）。検索の一致の強調は、表示中の表の中には出ない（一致に移ると原文になる）。
- クリックで置かれるカーソルは、クリックした文字の位置ではなく、そのセルの中身の末尾。
- 引用やリストの中の表、frontmatter の中は、表示しない。インラインコードの中の `|` は、GFM の仕様どおりセルの区切りになるので、そのセルは、コードとして表示されない（原文の文字のまま）。
- 構文木の解析が追いついていない範囲の表は、原文のまま。長い文書で、解析が届くと表示に変わる。
- 画像、参照リンク、HTML は、表示中の表の中でも原文の文字のまま。
- 表示中の表のスクリーンリーダーでの読み上げ（th と td の構造は、素の table 要素）は、確かめていない。

## 判断を見直す条件

- 実機（WKWebView）や実 IME で、表の出入りや変換中の表示に問題が出たとき。
- 表の中のセルを、表示のまま編集したい要望が出たとき（直接の編集は、本文の自動変更を伴いうるので、仕様 §5.2 の見直しとあわせて決める）。
- 行や列を足すキー操作、`|` をそろえるコマンドの要望が出たとき（Zettlr、VS Code の拡張の型）。
- 引用やリストの中の表を、表示したい要望が出たとき。
- 表に出入りしたときの高さの変化が、日常の使い方で気になるとき。
